### Configuration & Implementation

This will include all major steps and some commands. I'm not listing every command or step involved to recreate this setup. It is for overview purposes or how I achieved my home-lab.  

###### Mikrotik hEX S

**Hardening**
1. Download Winbox & connect device to router via ethernet cable
	- Bypassed firewall to connect via Winbox
2. Create admin user & password
	- Then delete default admin user account
3. Made sure NAT-PMP, UPNP, are disabled
	-  They are disabled by default 
4. Disable FTP, Telnet, API, API-SSL, & HTTP
5. Limit Winbox, SSH, & HTTPS to MGMT vlan subnet, 1 max session, & changed default port.  
6. Create self-signed ssl certificate for HTTPS
	- Upload to browser to avoid certificate warning
7. Adjust firewall rule #3 ICMP to restrict to hEX S subnet only. 
	- hEX S is now unreachable via ICMP to ISP subnet
8. IP neighbor discover set to LAN 
	- hEX S  uses this protocol to broadcast to subnet
9. After Routing steps 1 & 2 hEX S will be connected to internet; update bootloader & firmware.
	- System -> routerboard -> upgrade firmware -> reboot
	- System -> package -> check for updates
10. Shutdown any unused eth interface/ports

The steps above were implemented to harden the router & reduce attack surface to malicious actors. All admin privileges are set for only management vlan access via encrypted connections. 

**Routing**
1. ISP Pass-through Interface
	- Remove eth port# from existing bridge
	- Create new bridge named ISP_PASS
	- Add WAN port and eth port# to new bridge
		- Eth port# will be the one deleted from default bridge
2. ISP_PASS DHCP Client
	- For eth port# that was added to ISP_PASS disable DHCP Client
	- Add new dhcp and select ISP_PASS interface. 
	- ISP_PASS will now be a dhcp client to ISP router

The routing steps above allow the existing infrastructure in my home to pass ISP gateway DHCP via layer 2 bridge within the hEX S router. Existing switch and devices on the ISP subnet remain on there while maintaining my production network separate. 

**Verified Work** 
- Existing devices maintain ISP subnet IP's 
- hEX S is unreachable to ICMP via ISP subnet
- hEX S does receive ICMP on its own subnet
- hEX S HTTPS management portal is reachable
- On laptop connected to hEX S I'm using Parrot OS and firewall blocks winbox
	- Add firewall rules to accept port UDP 20561 (session) & UDP 5678 (discovery)

**Routed Link** 
1. Create a routed link between hEX S & Cisco 3560cx
	 - Click on bridge then ports tab
	 - Selected ethernet port# to use then remove from bridge 
2. Assign transit IP subnet to port 
	- Select IP, then addresses, and click on New
	- Assign IP subnet 192.168.x.x/30, select interface eth#, and apply/ok

Creating a routed link allows the hEX S to stop broadcasts from crossing the link, provides more bandwidth potential, and has a fast fail turnover. This is ideal for my setup since I want the Cisco to handle VLANs and ACLs.

**Static Route**
1. In IP menu within hEX S select routes
2. New route will use the destination address of all VLANs 
	- For VLANs can create multiple rules for each subnet or one large subnet if it uses the same IP class; best practice is to create multiple rules for each vlan subnet
3. Gateway for this route is routed link IP of Cisco switch, i.e 192.168.x.x/30

This informs the hEX S that any IP traffic with VLAN subnet should be sent to the gateway, the Cisco 3560cx in this case, for routing. Otherwise it would see that traffic as not part of its own subnet and drop it. 

###### Cisco 3560cx

!Always "Write Memory" once run commands and verify your design! I forgot to write my configuration to memory and had to redo all of these steps. 

**Connecting to hardware**
1. Used a microusb to console connection 
2. Factory reset hardware, since it's used hardware
3. Install putty on Parrot OS and ls /dev/tty to find serial connection
	- /dev/ttyACM0 was listed connected device
4. Change permissions to CHMOD 660 for /dev/ttyACM0 
	- If not you will get a permissions error when trying to connect via putty

**Routed Link Port**
1. In exec mode assign an ethernet port for routed link 
	- Enable for exec mode
	- IP routing, then select interface gigabiteth 0/port#
	- No switchport to turn interface into a layer 3 routed port 
	- IP address and input routed link Cisco IP, i.e 192.168.x.x   255.255.255.252 (/30)
	- No shutdown & exit/end/write memory
2. Verify routed link is working by pinging Cisco IP from hEX S terminal & vice versa
	- Had to modify hEX S firewall to allow ICMP from routed link subnet
		- To find rule blocking Cisco ICMP on hEX S print /ip firewall filter print stats
		- Ping from Cisco to hEX S
		- Then run hEX S firewall filter print stats again and see which counter went up
		- Then adjusted firewall rule to allow routed link subnet ICMP

This configures & verifies communication between the hEX S & Cisco 3560cx through the routed link connection. 


**Static Routes**
1. Adding a static IP route for any traffic to hEX S through routed link 
	- conf t -> IP route 0.0.0.0 0.0.0.0 hEX S IP 
2. Verify IP routing works by pinging hEX S management IP & external DNS server

This creates routing tables for any IP traffic on Cisco switch to the hEX S through the routed link IP.


**VLAN Creation** 
1. Decide on VLAN names & subnets beforehand
	- Enable -> conf t -> vlan# -> name xxxx -> exit
	- Interface vlan# -> description xxxx -> IP address x.x.x.1  255.255.255.x -> no shutdown
	- Repeat for every vlan

This creates vlan, gives it a name, then description, then assign SVI (gateway) for vlan subnet, and enable layer 3 routing for the vlan. I'm using variables for my personal subnets but including the numbers that are important.

**VLAN Port Mapping**
1. Decide ports/interfaces that will belong to VLANs beforehand
	- Enable -> conf t -> interface range gigabiteth0/#-# -> description xxxx -> switchport mode access -> switchport access vlan# -> exit/end/write memory
	- Repeat for every vlan
2. To verify port mapping: show vlan brief
3. Shutdown unused ports for security hardening
	- By assigning ports/interfaces to vlan with no SVI

This allows your switch to have VLANs mapped out to the ports/interfaces you want and also shutdown any unused interfaces; by assigning them to a vlan with no internet or ability to talk to other vlans. 

**Cisco 3560cx Security Hardening**
1. Disabled Telnet & Limit SSH to 1 session
2. Disabled port 80 & 443 (HTTP/HTTPS)
3. Disable Cisco Discover Protocol (CDP)

Shutdown unencrypted connections and any http/s server since I only want to connect via serial cable locally. 

**Build DHCP Pools**
1. Excluded dhcp IP addresses for every VLAN SVI
	- IP dhcp excluded-address (VLAN SVI IP)
2. DHCP Pool for 1 VLAN
	- IP dhcp pool VLAN_NAME
	- Network (VLAN_IP Subnet) (Subnet Mask) 
	- Default-Router (VLAN_SVI IP)
	- DNS-server 8.8.8.8 x.x.x.x
	- Exit/end/write memory
	- Repeat for every vlan dhcp pool
3. Verify with command: show ip dhcp binding

Build the DHCP pools for every vlan and you can define SVI & DNS for every vlan.

**Management VLAN Issue**
1. Issue related to hEX S management HTTPS portal and not being reachable from Cisco 3560cx management vlan
	- Found issue main symptoms by running a packet sniffer while trying to connect to hEX S
	- hEX S packet sniffer showed Cisco trying to connect and TLS handshake not completing
	- After syn, syn/ack working fine the ack would not finish; then there would be a push/ack over MTU size and loop until fin/ack then the cycle would repeat
2. Change default port for HTTPS access. 
	- Fixed issue!

This was a very time consuming issue. I initially tried the trick of counting the firewall rule counters after trying to connect. This would point out which rule was blocking the connection but no counter would increase. Since there was no counter increase the next step was to run a packet sniffer on the hEX S terminal while trying to connect. 

Then print the packet sniffer results in the hEX S terminal and this showed the connection trying to complete the TLS handshake and dropping connection due to not being able to complete the TLS handshake. I input all this information into my AI agent and it referred to an issue with the default port for HTTPS access. I changed the default port and issue was fixed! 


**VLAN Access Control Lists**
1. I decided how I wanted traffic to be routed throughout my VLANs.
2. For example:
	- Management VLAN doesn't not have access to internet 
	- MGMT vlan does not have communication with outside of it's own subnet & the routed link subnet
		- This way I can communicate with hEX S HTTPS admin portal but stop vlan hopping into my MGMT VLAN
3. Each VLAN has its own rules but some key points when writing these ACL's
	- These are ip access-list extended (insert name here)
	- Permit ip (Vlan subnet) (Vlan subnet mask wildcard) (Vlan subnet) (Vlan subnet mask wildcard)
	- Permit IP is also used for allowing communication between VLANs (vlan subnet) or out to the internet (0.0.0.0) or both
	- deny ip any any will stop traffic not allowed in previous ACL commands
	- They are structured by number like a firewall and will go sequentially
	- Then you must apply ACL to VLAN once done

 I have 6 vlans and each has slightly different ACL's. Some are allowed to communicate to each other but most are not. All but MGMT VLAN can reach the internet. I also restricted DNS use outside of those specified in my DHCP pools. One important note is to use subnet wildcard mask for subnet mask when wiring ACLs. 

**Trunk Port to Flint 2**
1. Conf T ->interface gigabitheth0/# -> description Trunk to AP -> switchport mode trunk -> switchport trunk native vlan vlan# -> switchport trunk allowed vlan #,#,# -> exit/end/write memory
2. Verify trunk port by connecting port to AP and running command: show interfaces trunk

This is to pass all the VLANs from the Cisco 3560cx to the Flint 2 which will be used in an Access Point Configuration.

***ISSUES***

There are massive issues (broadcast storms, vlans cant be assigned, configurations wont save, etc.) with using Glinet stock firmware, and even issues with openWRT Vanilla, when incorporating VLANs into an access point (AP) design. 

Instead of going into all the details this will save you a lot of time if you are trying to use the Flint 2 as an AP and passing VLANs into the Flint 2

1. Immediately download openWRT Vanilla and install. DO NOT USE GLINET STOCK FIRMWARE
2. SSH into Flint 2 and use CLI to assign VLANs to where you want. 
	- Look below for example commands
	- My commands are modified to fit my network architecture
3. The WiFi commands to create and assign SSIDs to VLANs didn't work
	- It created the SSIDs on the correct radio but not all SSIDs (I have more than 1 network)
	- It didn't map out the VLANs to the SSIDs

**VLAN Configurations**
 1. CLEAN & CONFIGURE NETWORK SWITCHPORTS
	 Clear default rules
	uci -q delete network.@bridge-vlan
	uci -q delete network.@bridge-vlan
	
	VLAN 10 (Management): Tagged on Cisco Trunk (lan1), Tagged to CPU (bridge)
	-  lan2 an untagged fallback access port for VLAN 10 so you can plug in locally to manage it.
	uci add network bridge-vlan
	uci set network.@bridge-vlan[-1].device='br-lan'
	uci set network.@bridge-vlan[-1].vlan='10'
	uci set network.@bridge-vlan[-1].ports='lan1:t lan2:u* bridge:t'
	
	VLAN 20 (Main Wi-Fi): Tagged on Cisco Trunk, Untagged access port on lan3
	uci add network bridge-vlan
	uci set network.@bridge-vlan[-1].device='br-lan'
	uci set network.@bridge-vlan[-1].vlan='20'
	uci set network.@bridge-vlan[-1].ports='lan1:t lan3:u*'
	
	VLAN 30 (Guest Wi-Fi): Tagged on Cisco Trunk, Untagged access port on lan4
	uci add network bridge-vlan
	uci set network.@bridge-vlan[-1].device='br-lan'
	uci set network.@bridge-vlan[-1].vlan='30'
	uci set network.@bridge-vlan[-1].ports='lan1:t lan4:u*'
	
2. FORCE MANAGEMENT INTERFACE TO USE TAGGED VLAN 10
	This instructs OpenWrt to send its DHCP request explicitly tagged as VLAN 10
	
	uci set network.lan.device='br-lan.10'
	uci set network.lan.proto='dhcp'
	uci commit network
	
3. MAP WIRELESS INTERFACES TO TAGGED VLANS (DUAL-BAND)
	
	VLAN 20: MAIN WI-FI (Dual-Band)
	
	Configure 5GHz for Main Wi-Fi
	uci set wireless.default_radio0.network='br-lan.20'
	uci set wireless.default_radio0.ssid='My_Secure_Main_WiFi'
	
	Create a new interface on the 2.4GHz radio for Main Wi-Fi
	uci add wireless wifi-iface
	uci set wireless.@wifi-iface[-1].device='radio1'
	uci set wireless.@wifi-iface[-1].mode='ap'
	uci set wireless.@wifi-iface[-1].network='br-lan.20'
	uci set wireless.@wifi-iface[-1].ssid='My_Secure_Main_WiFi'
	
	Configure 2.4GHz for Guest Wi-Fi
	uci set wireless.default_radio1.network='br-lan.30'
	uci set wireless.default_radio1.ssid='My_Secure_Guest_WiFi'
	
	Save wireless configuration changes
	uci commit wireless
	
4.  SYSTEM REBOOT
	reboot
